1. Синтаксис языка C, использованный в коде

1.1. Базовые типы с фиксированной шириной

В встраиваемом коде используют типы из <stdint.h> — они гарантируют размер независимо от платформы.

ТипРазмерДиапазонГде в вашем коде
uint8_t1 байт0…255возврат urr_check_crc()
uint32_t4 байта0…4 294 967 295urr_irq_flag, freq_code
u8, u16, u321/2/4 байтато же (Xilinx-алиасы)XIntc_Enable(..., u8 Id)
UINTPTRразмер указателяадресBaseAddress в XIntc_Config
Совет: в своём коде всегда используйте uint32_t/uint8_t из stdint.h, а не int/char — размер последних зависит от компилятора и архитектуры.

1.2. Указатели

/* Указатель на uint32_t */
uint32_t *freq_code;

/* Передача указателя в функцию — она сможет изменить значение */
uint8_t urr_read_freqcode(uint32_t *freq_code)
{
    *freq_code = Xil_In32(URR_RESULT) & 0x00FFFFFF;
    return 0;
}

/* Вызов: передаём адрес переменной через & */
uint32_t code;
urr_read_freqcode(&code);   // внутри *freq_code изменит code

1.3. Ключевое слово volatile

Говорит компилятору: «эта переменная может измениться в любой момент, не кэшируй её в регистре». Обязательно для переменных, которые меняются в прерываниях.

/* Без volatile компилятор может решить,
   что urr_irq_flag не меняется в цикле,
   и превратить while в бесконечный */
volatile uint32_t urr_irq_flag = 0;

/* В main: */
while (!urr_irq_flag && timeout--) { ... }
Важно: все флаги, которые выставляются в ISR и читаются в main(), должны быть volatile. Иначе оптимизатор сломает логику.

1.4. Функции и прототипы

/* Прототип (объявление) — в .h */

/* Определение (реализация) — в .c */

1.6. Циклы и условия

/* while с пост-декрементом: сначала проверка timeout != 0,
   потом уменьшение. Когда timeout == 0 — выход */

/* if / else if / else */

2. Битовые поля, union и #pragma pack

В urr.h структура телеметрии собрана из битовых полей внутри union:

#pragma pack( push, 1 )
typedef struct {
    union {
        struct {
            uint32_t connected :1;   // бит 0
            uint32_t ready     :1;   // бит 1
            uint32_t err_crc   :1;   // бит 2
            uint32_t res       :5;   // биты 3..7
        };
        uint8_t value;             // доступ ко всем 8 битам сразу
    };
} t_urr_tel;
#pragma pack( pop )

Что это даёт

  • Битовые поля (connected :1) позволяют обращаться к отдельным битам по имени.
  • union накладывает struct и value на одну и ту же память: можно писать в поля по отдельности, а читать/передавать все 8 бит одним байтом.
  • Анонимный union (без имени) — поля connected, ready, value доступны напрямую как tel.connected, tel.value.
  • #pragma pack(push, 1) — убирает выравнивание, чтобы структура занимала ровно 1 байт (важно для передачи по шине/сети).
/* Использование в main.c */
t_urr_tel tel = urr_get_tel();

xil_printf("Tel: connected=%u ready=%u err_crc=%u (val=0x%02X)\r\n",
           (unsigned)tel.connected,   // доступ к биту
           (unsigned)tel.ready,
           (unsigned)tel.err_crc,
           (unsigned)tel.value);    // весь байт
Порядок битов в битовых полях зависит от компилятора (little-endian vs big-endian). На MicroBlaze (little-endian) connected — младший бит байта. Не полагайтесь на это при обмене с внешними устройствами без явной спецификации.

3. Препроцессор: #define, #ifdef, #ifndef

3.1. Макросы-константы

#define URR_BASE        XPAR_AXI_BRAM_CTRL_0_S_AXI_BASEADDR
#define URR_CTRL        (URR_BASE + 0x00)
#define URR_CMD         (URR_BASE + 0x08)
#define UART_STATUS_DONE    0x01
#define CRC_STATUS_MATCH    0x02

Препроцессор просто подставляет текст. URR_CTRL разворачивается в (0xC0000000 + 0x00).

3.2. Условная компиляция

#ifndef SDT
    u16 DeviceId;
#else
    char *Name;
#endif

Если макрос SDT не определён — компилируется первая ветка, иначе вторая. Так поддерживают две версии BSP (старую и System Device Tree).

3.3. Защита заголовка (include guard)

#ifndef URR_H
#define URR_H

/* содержимое заголовка */

#endif /* URR_H */

Не даёт включить urr.h дважды — иначе будут ошибки «redefinition».

3.4. Внешние переменные: extern

/* urr.h — только объявление, память не выделяется */
extern volatile uint32_t urr_irq_flag;
extern volatile uint32_t urr_connect_flag;

/* urr.c — определение, здесь выделяется память */
volatile uint32_t urr_irq_flag     = 0;
volatile uint32_t urr_connect_flag = 0;

extern говорит: «переменная существует где-то в другом .c». Без него линкер выдаст «multiple definition».

4. XIntc: устройство контроллера прерываний

4.1. Что такое AXI INTC

Это аппаратный блок Xilinx, который собирает сигналы прерываний от периферии (у вас — от модуля URR) и передаёт их процессору MicroBlaze одним сигналом IRQ. Внутри — 32 входа (в каскаде — больше).

URR (irq_o)     ──┐
URR (irq_con_o) ──┤
...             ──┼──► AXI INTC ──► MicroBlaze (IRQ)
другие IP       ──┘

4.2. Ключевые регистры INTC

РегистрСмещениеНазначение
ISR0x00Interrupt Status — какие прерывания сейчас pending
IPR0x04Interrupt Pending — pending, игнорируя маску
IER0x08Interrupt Enable — какие источники разрешены
IAR0x0CAcknowledge — сброс pending-бита
SIE0x10Set Enable — установить бит в IER
CIE0x14Clear Enable — сбросить бит в IER
MER0x1CMaster Enable — общее разрешение контроллера

4.3. Структура XIntc_Config

Статическая конфигурация (генерируется Xilinx-тулами в xintc_g.c):

  • DeviceId / Name — ID или имя устройства
  • BaseAddress — базовый адрес регистров
  • NumberofIntrs — число входов
  • IntcType — 0=no cascade, 1=primary, 2=secondary, 3=last
  • HandlerTable[] — таблица обработчиков (по одному на вход)

4.4. Runtime-структура XIntc

static XIntc InterruptController;   // в вашем main.c

Хранит CfgPtr (указатель на конфигурацию), IsReady, IsStarted и т.п. Все вызовы XIntc_* работают именно с этим экземпляром.

4.5. Жизненный цикл драйвера

ФункцияЧто делает
XIntc_Initialize()Находит конфигурацию по DeviceId, обнуляет таблицу
XIntc_Connect()Привязывает обработчик к источнику
XIntc_Start()Пишет MER — включает контроллер (+ slave в каскаде)
XIntc_Enable()Ставит бит в IER — разрешает конкретный источник
XIntc_Disable()Сбрасывает бит в IER
XIntc_Acknowledge()Пишет в IAR — сбрасывает pending

5. Xil_Exception: обработка исключений процессора

Это отдельный уровень. INTC выдаёт сигнал на вход MicroBlaze, а Xil_Exception решает, какая функция вызовется при этом сигнале.

ФункцияНазначение
Xil_ExceptionInit()Пустая заглушка (для совместимости)
Xil_ExceptionRegisterHandler()Записать обработчик в XExc_VectorTable[Id]
Xil_ExceptionEnable()Установить биты EE/IE в MSR (MicroBlaze)
Xil_ExceptionDisable()Сбросить EE/IE

5.1. Что происходит при IRQ

  1. Процессор MicroBlaze принимает сигнал IRQ.
  2. Аппаратно переходит на вектор исключения.
  3. BSP-код смотрит XExc_VectorTable[XIL_EXCEPTION_ID_INT].Handler.
  4. Вызывает его с аргументом Data — у вас это &InterruptController.
  5. Это XIntc_InterruptHandler() — он читает ISR, находит pending-биты и вызывает соответствующие обработчики из HandlerTable.
  6. Ваш urr_irq_handler() выставляет urr_irq_flag++.
MicroBlaze IRQ
    │
    ▼
XExc_VectorTable[XIL_EXCEPTION_ID_INT]
    │
    ▼
XIntc_InterruptHandler(&InterruptController)
    │
    ├── читает ISR
    ├── для каждого pending бита:
    │      HandlerTable[id].Handler(HandlerTable[id].CallBackRef)
    │
    ▼
urr_irq_handler()  →  urr_irq_flag++

6. Разбор вашего кода

6.1. main.c — последовательность инициализации

1

Инициализация INTC

Status = XIntc_Initialize(&InterruptController,
                            XPAR_AXI_INTC_0_DEVICE_ID);
if (Status != XST_SUCCESS) { ... }

Находит конфигурацию по DeviceId, обнуляет HandlerTable, ставит IsReady.

2

Подключение обработчиков

XIntc_Connect(&InterruptController,
              XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR,
              (XInterruptHandler)urr_irq_handler, 0);

XIntc_Connect(&InterruptController,
              XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR,
              (XInterruptHandler)urr_connect_handler, 0);

Заполняет HandlerTable[id].Handler для двух источников: irq_o (готовность кода) и irq_con_o (подключение). CallBackRef = 0 — обработчики его не используют.

3

Запуск контроллера и разрешение источников

XIntc_Start(&InterruptController, XIN_REAL_MODE);
XIntc_Enable(&InterruptController,
             XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR);
XIntc_Enable(&InterruptController,
             XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR);

Start пишет MER (master + hardware enable). Enable ставит биты в IER для двух источников.

4

Регистрация обработчика исключения процессора

Xil_ExceptionInit();   // no-op
Xil_ExceptionRegisterHandler(XIL_EXCEPTION_ID_INT,
                             (Xil_ExceptionHandler)XIntc_InterruptHandler,
                             &InterruptController);

Теперь при IRQ процессор вызовет XIntc_InterruptHandler, который «разгребёт» INTC.

5

Инициализация URR

urr_init();   // сбрасывает флаги, включает модуль (CTRL = 1)
6

Разрешение исключений процессора

Xil_ExceptionEnable();   // MSR |= EE | IE
Порядок критичен: Xil_ExceptionEnable() вызывается после регистрации всех обработчиков и urr_init(). Если включить раньше — можно поймать прерывание до готовности.
7

Основной цикл

while (1) {
    tel = urr_get_tel();
    if (tel.connected && tel.ready) {

        urr_irq_flag = 0;              // сброс флага
        urr_get_freqcode(addr);          // команда модулю

        uint32_t timeout = 100;
        while (!urr_irq_flag && timeout--) {
            usleep(1000);                // ждём ISR до 100 мс
        }

        if (urr_irq_flag) {
            uint32_t freq_code;
            if (urr_read_freqcode(&freq_code) == 0) {
                xil_printf("addr=%u freq_code=0x%06X\r\n", ...);
            }
        }
        ...
    }
    addr++;
    if (addr > 50) addr = 1;
    usleep(500000);
}

Циклически проходим адреса 1..50, для каждого ждём прерывание irq_o и читаем результат.

6.2. urr.c — обработчики и API

/* ISR: готовность кода частоты */
void urr_irq_handler(void *ref)
{
    (void)ref;          // подавляем warning "unused parameter"
    urr_irq_flag++;    // main увидит и продолжит
}

/* ISR: подключение URR */
void urr_connect_handler(void *ref)
{
    (void)ref;
    urr_connect_flag++;
    s_connected = 1;
}
Правила ISR:
  • Коротко: без xil_printf, без usleep, без блокирующих вызовов.
  • Только volatile-переменные и регистры.
  • Не вызывать функции, которые могут ждать.
  • Если нужно передать данные в main — писать в volatile буфер/флаг.

6.3. urr_check_crc() — polling-ожидание

uint8_t urr_check_crc(void)
{
    uint32_t timeout = 1000000;

    Xil_Out32(URR_CRC_START, 0x1);   // запуск

    while (timeout--) {
        uint32_t st = Xil_In32(URR_CRC_STATUS);
        if (st & CRC_STATUS_DONE) {
            if (st & CRC_STATUS_MATCH) {
                s_err_crc = 0;
                return 0;   // OK
            } else {
                s_err_crc = 1;
                return 1;   // FAIL
            }
        }
        usleep(1);
    }
    s_err_crc = 1;
    return 1;               // таймаут
}

Это не прерывание, а опрос регистра статуса с таймаутом. Такой подход проще, но занимает процессор. Прерывание эффективнее, но требует больше кода.

7. Как настроить контроллер прерываний на MicroBlaze

7.1. В Vivado (аппаратная часть)

  1. Добавить IP AXI Interrupt Controller.
  2. Соединить входы intr[0..N-1] с сигналами прерываний периферии (у вас — irq_o на вход 1, irq_con_o на вход 0).
  3. Выход interrupt INTC соединить с INTERRUPT MicroBlaze.
  4. В настройках MicroBlaze включить Use Interrupt и выбрать AXI INTC как контроллер.
  5. Сгенерировать bitstream и экспортировать .xsa.

7.2. В Vitis/SDK (программная часть)

После импорта .xsa автоматически генерируются:

  • xparameters.h — макросы XPAR_AXI_INTC_0_DEVICE_ID, XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR и т.п.
  • xintc_g.c — массив XIntc_ConfigTable[] с конфигурациями INTC.
Имена ID прерываний формируются как XPAR_<INTC>_<IP>_<СИГНАЛ>_INTR. Именно их вы передаёте в XIntc_Connect и XIntc_Enable. Не путайте с номером входа — драйвер сам сопоставит.

7.3. Шаблон инициализации (универсальный)

static XIntc Intc;

int setup_interrupts(void)
{
    int Status;

    /* 1. Инициализация */
    Status = XIntc_Initialize(&Intc, XPAR_AXI_INTC_0_DEVICE_ID);
    if (Status != XST_SUCCESS) return XST_FAILURE;

    /* 2. Подключение всех нужных обработчиков */
    XIntc_Connect(&Intc, INTR_ID_1, handler1, ref1);
    XIntc_Connect(&Intc, INTR_ID_2, handler2, ref2);

    /* 3. Запуск контроллера */
    XIntc_Start(&Intc, XIN_REAL_MODE);

    /* 4. Разрешение источников */
    XIntc_Enable(&Intc, INTR_ID_1);
    XIntc_Enable(&Intc, INTR_ID_2);

    /* 5. Регистрация обработчика исключения процессора */
    Xil_ExceptionInit();
    Xil_ExceptionRegisterHandler(XIL_EXCEPTION_ID_INT,
                                 (Xil_ExceptionHandler)XIntc_InterruptHandler,
                                 &Intc);

    /* 6. Только теперь разрешаем прерывания в процессоре */
    Xil_ExceptionEnable();

    return XST_SUCCESS;
}
Порядок важен: сначала Connect (кто обработает), потом Start (включить контроллер), потом Enable (разрешить источник), потом Xil_ExceptionRegisterHandler (процессор знает, кого звать), и только в конце Xil_ExceptionEnable (разрешить прерывания в CPU).

7.4. Каскадный режим (Cascade)

Если входов больше 32, INTC соединяют каскадом: мастер + slave. В коде это прозрачно — XIntc_Connect и XIntc_Enable сами определяют по Id > 31, к какому контроллеру обратиться. Главное — правильно выставить IntcType в конфигурации (генерируется автоматически).

7.5. Что происходит в железе при Enable

XIntc_Enable(&Intc, Id)
    │
    ├── если Id <= 31:
    │       Mask = 1 << Id
    │       IER |= Mask          (IER мастер-контроллера)
    │
    └── если Id > 31:
            SlaveId = Id / 32
            Mask    = 1 << (Id % 32)
            Slave.IER |= Mask

8. Частые ошибки и как их избежать

СимптомПричинаРешение
ISR не вызывается Забыли Xil_ExceptionEnable() Вызвать после регистрации всех обработчиков
ISR вызывается один раз и больше нет Не сбросили pending в INTC XIntc_InterruptHandler делает это автоматически, но проверьте, что периферия сняла свой сигнал
urr_irq_flag не меняется в main Нет volatile Объявить volatile uint32_t urr_irq_flag
Обработчик срабатывает не для того источника Перепутаны ID прерываний Сверить с xparameters.h
Прерывание до готовности системы Xil_ExceptionEnable() вызван слишком рано Вызывать последним в цепочке инициализации
Зависание в ISR Вызов usleep/xil_printf в ISR Только флаги и регистры в ISR, вывод — в main
«Multiple definition» при линковке volatile uint32_t urr_irq_flag определён в .h extern в .h, определение — в одном .c

8.1. Отладка прерываний

  • Поставьте breakpoint в ISR — если не срабатывает, проверьте MER, IER, MSR в отладчике.
  • Счётчики urr_irq_flag и urr_connect_flag — простой способ убедиться, что ISR вообще вызывается.
  • Xil_In32(URR_BASE + 0x00) — читайте ISR вручную, чтобы понять, какие биты pending.
  • Если INTC в каскаде — проверьте, что slave тоже запущен (XIntc_Start проходит по всем).

8.2. Минимальный чек-лист запуска

  1. ☐ В Vivado: INTC добавлен, входы соединены, выход → MicroBlaze INTERRUPT.
  2. ☐ В xparameters.h есть XPAR_AXI_INTC_0_DEVICE_ID и ID ваших прерываний.
  3. ☐ XIntc_Initialize → XST_SUCCESS.
  4. ☐ XIntc_Connect для каждого источника.
  5. ☐ XIntc_Start(XIN_REAL_MODE).
  6. ☐ XIntc_Enable для каждого источника.
  7. ☐ Xil_ExceptionRegisterHandler(XIL_EXCEPTION_ID_INT, XIntc_InterruptHandler, &Intc).
  8. ☐ Xil_ExceptionEnable() — последним.
  9. ☐ Все флаги ISR ↔ main — volatile.
  10. ☐ В ISR нет блокирующих вызовов.
