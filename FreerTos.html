FreeRTOS: теория и миграция URR-драйвера с bare metal

Сводная страница: как устроена FreeRTOS, чем она отличается от bare metal и Linux/Windows, и что конкретно нужно изменить в URR-драйвере при переходе на FreeRTOS.

Что такое FreeRTOS

FreeRTOS — это ядро реального времени. Вместо одного большого while(1) вы создаёте несколько независимых задач, а ядро само решает, какая из них должна выполняться в данный момент.

В проекте, который вы показывали ранее, FreeRTOS используется как основа всей прошивки: задачи обмена по RF, SPI, Ethernet, мониторинга, сервиса, обработки MCU.

1. Задачи и планировщик

Задача — обычная C-функция, которая никогда не должна возвращаться:

static void Tx_Task(void* params)
{
    while(1)
    {
        xSemaphoreTake(TxSem, portMAX_DELAY);
        /* ... */
    }
}

Создаётся через xTaskCreate:

xTaskCreate(Tx_Task, "Tx_Task", TX_TASK_STACK,
            NULL, TX_TASK_PRIORITY, &TxTaskHandl);
ПараметрЗначение
1Функция задачи
2Имя (для отладки)
3Размер стека
4Параметр, передаваемый в задачу
5Приоритет
6Указатель на хэндл задачи

Планировщик запускается в main:

int main(void)
{
    xTaskCreate(Init_Task, "Init_Task", INIT_TASK_STACK,
                NULL, INIT_TASK_PRIORITY, &InitTaskHandl);
    vTaskStartScheduler();

    while(1);
}
Важно

После vTaskStartScheduler() управление больше не возвращается в main. Дальше ядро переключает задачи.

2. Приоритеты

В FreeRTOS чем больше число, тем выше приоритет.

#define INIT_TASK_PRIORITY        9
#define TX_TASK_PRIORITY          9
#define RX_TASK_PRIORITY          8
#define RX_MASTER_QUEUE_PRIORITY  7
#define SPI_RX_TASK_PRIORITY      6
#define SPI_TX_TASK_PRIORITY      6
#define WIZNET_TASK_PRIORITY      5
#define MONITOR_TASK_PRIORITY     3
#define SERVICE_TASK_PRIORITY     2

То есть Tx_Task и Init_Task — самые приоритетные. Если Tx_Task готова к выполнению, она вытеснит Rx_Task, Monitor_Task и т.д.

Планировщик всегда выбирает самую приоритетную готовую задачу. Если несколько задач имеют одинаковый приоритет, они могут выполняться по кругу, если включено time slicing.

3. Состояния задачи

  • Running — выполняется прямо сейчас;
  • Ready — готова выполняться, но ждёт CPU;
  • Blocked — ждёт событие: семафор, очередь, vTaskDelay;
  • Suspended — приостановлена явно.

Почти все задачи в вашем проекте большую часть времени находятся в Blocked:

xSemaphoreTake(TxSem, portMAX_DELAY);

Это означает: «спать, пока не дадут TxSem». Пока задача спит, CPU может занимать другие задачи.

4. Семафоры

Семафоры — механизм синхронизации и сигнализации. В проекте есть:

  • бинарные: TxIpDmaDone, RxIpDmaDone, DmaWiznetSem, FCSem1 и др.;
  • счётные: TxSem, RxSem, SpiTxSem, SpiRxIpSem;
  • мьютексы: DmaRfMutex, DmaEthMutex, DmaSpiRxMutex и др.
Из задачи
xSemaphoreTake(TxSem, portMAX_DELAY);
/* ... */
xSemaphoreGive(TxSem);
Из прерывания
BaseType_t woken = pdFALSE;
xSemaphoreGiveFromISR(TxSem, &woken);
portYIELD_FROM_ISR(woken);
Правило

Из ISR нельзя вызывать обычные xSemaphoreGive. Только ...FromISR и обязательно с &woken, иначе не произойдёт немедленное переключение на разбуженную задачу.

5. Очереди

Очереди передают данные между задачами и прерываниями. В проекте:

PointerQueue_Eth2Rf      = xQueueCreate(RF_TX_FIFO_NUM_PIECE, sizeof(uint8_t));
PointerQueue_PB_Eth2Rf   = xQueueCreate(1, sizeof(uint8_t));
PointerQueue_Spi2Tx      = xQueueCreate(SPI_TX_FIFO_NUM_PIECE, sizeof(uint8_t));
IRQ_TOUT1_TOUT2_OR_RX    = xQueueCreate(4, sizeof(uint8_t));

Очереди хранят не сами большие пакеты, а индексы или указатели на статические буферы. Например, в Rf_Queue_Add: 

xQueueSend(PointerQueue_Eth2Rf, &UserDataQueue.head, 0);

Сами данные лежат в UserDataQueue.buf[...].

Из прерывания:

xQueueSendFromISR(IRQ_TOUT1_TOUT2_OR_RX, &IRQ_CODE, &woken);

6. Прерывания и задачи

Схема работы:

  1. Железное прерывание срабатывает.
  2. ISR делает минимум: отправляет событие в очередь или даёт семафор.
  3. Задача просыпается и делает основную работу.
void Tx_EOP_Irq_Handle(void *CallBackRef)
{
    if ((SysSettings.rfRole == SLAVE) && (LocalStateFc.FcRun == 0)) {
        BaseType_t woken = pdFALSE;
        xSemaphoreGiveFromISR(TxSem, &woken);
        portYIELD_FROM_ISR(woken);
    }
}

Или через очередь:

void TOUT1_Irq_Handle(void *CallBackRef)
{
    uint8_t code = TIMEOUT_TOUT1_EVENT;
    BaseType_t woken = pdFALSE;
    xQueueSendFromISR(IRQ_TOUT1_TOUT2_OR_RX, &code, &woken);
    portYIELD_FROM_ISR(woken);
}

portYIELD_FROM_ISR нужен, чтобы после выхода из ISR сразу переключиться на задачу, которая стала более приоритетной.

7. Задержки

vTaskDelay переводит задачу в Blocked на заданное число тиков:

vTaskDelay(1300);          /* 1300 мс при configTICK_RATE_HZ = 1000 */
vTaskDelay(MON_TASK_PERIOD);

8. Как это устроено в вашем проекте

Порядок запуска:

  1. main создаёт Init_Task с приоритетом 9.
  2. Запускается планировщик.
  3. Init_Task инициализирует железо, очереди, семафоры, создаёт остальные задачи.
  4. В конце Init_Task вызывает vTaskDelete(NULL) и удаляет себя.
  5. Дальше работают задачи:
    • Tx_Task — ждёт TxSem, берёт пакет из RF-очереди, настраивает TX IP, запускает DMA, ждёт TxIpDmaDone, стартует передачу.
    • Rx_Task — ждёт RxSem, читает телеметрию RX, принимает данные через DMA, отправляет клиенту.
    • Spi_Rx_Task — ждёт SpiRxIpSem, принимает Ethernet-пакет, парсит его.
    • Spi_Tx_Task — ждёт SpiTxSem, берёт ответ из SPI-очереди и отправляет через DMA.
    • Monitor_Task — периодически шлёт ping и обновляет RSSI/температуру.
    • Service_Task — обрабатывает частотную коррекцию.
    • MCU_Exch_IP_req_Task — обрабатывает запросы от MCU.

9. Real-time и Linux/Windows

FreeRTOS — это RTOS. Её цель — не «быстрее», а предсказуемее. Она даёт механизмы, чтобы гарантировать выполнение важной задачи в срок.

СистемаДетерминизмКогда подходит
Bare metal Очень высокий, если код простой и аккуратный Простые устройства, важна каждая микросекунда
FreeRTOS Хороший: латентность переключения — единицы мкс Сложные встраиваемые системы: RF, SPI, Ethernet, несколько задач
Linux По умолчанию непредсказуемый. С PREEMPT_RT — близок к hard real-time Мощные системы, где нужны драйверы, сеть, файловая система
Windows Не hard real-time Офисные, пользовательские задачи
Правильная формулировка

Не «FreeRTOS исполнит во время, а Linux/Windows/bare metal — нет». А так: bare metal может быть самым детерминированным, пока система простая; FreeRTOS даёт инструменты для проектирования системы с предсказуемыми сроками; Linux/Windows обычно не подходят для hard real-time, хотя Linux с PREEMPT_RT — может.

10.1 Конфликт адресов BRAM

Проверьте в первую очередь

В Port.h проекта MCU_BASE_ADDR = XPAR_AXI_BRAM_CTRL_0_S_AXI_BASEADDR, а в URR-драйвере URR_BASE — тот же адрес. Это один и тот же BRAM-контроллер. Либо разнесите адреса в одном окне, либо пересадите URR на другой BRAM-контроллер. 

#define URR_BASE  XPAR_AXI_BRAM_CTRL_5_S_AXI_BASEADDR   /* не CTRL_0! */

10.2 Прерывания: заменяем XIntc на Interrupt_Add_Irq

Шаг 1. В SysAPI_Irq_Init() добавить регистрацию URR-прерываний:

Interrupt_Add_Irq(XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR,   urr_irq_handler);
Interrupt_Add_Irq(XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR, urr_connect_handler);

Шаг 2. В Interrupt.c в switch(hwId) добавить case-ы:

case XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR:
    XConnectToInterruptCntrl(
        XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR,
        IrqList.irqObj[i].irqHandler, NULL,
        XPAR_AXI_INTC_0_BASEADDR | 0x01);
    XEnableIntrId(XPAR_AXI_INTC_0_UART_TOP_0_IRQ_O_INTR,
                   XPAR_AXI_INTC_0_BASEADDR | 0x01);
    break;

case XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR:
    XConnectToInterruptCntrl(
        XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR,
        IrqList.irqObj[i].irqHandler, NULL,
        XPAR_AXI_INTC_0_BASEADDR | 0x01);
    XEnableIntrId(XPAR_AXI_INTC_0_UART_TOP_0_IRQ_CON_O_INTR,
                   XPAR_AXI_INTC_0_BASEADDR | 0x01);
    break;

Шаг 3. Ничего из XIntc_Initialize / XIntc_Start / Xil_ExceptionRegisterHandler в URR-драйвер не переносим — это всё делает Interrupt_Init().

10.3 ISR и семафоры

ISR должны быть короткими: только дать семафор или очередь.

#include "FreeRTOS.h"
#include "semphr.h"

SemaphoreHandle_t UrrFreqSem;   /* даётся из irq_o */
SemaphoreHandle_t UrrConSem;    /* даётся из irq_con_o */

static volatile uint8_t s_connected = 0;
static volatile uint8_t s_err_crc   = 0;

void urr_irq_handler(void *ref)
{
    BaseType_t woken = pdFALSE;
    xSemaphoreGiveFromISR(UrrFreqSem, &woken);
    portYIELD_FROM_ISR(woken);
}

void urr_connect_handler(void *ref)
{
    BaseType_t woken = pdFALSE;
    s_connected = 1;
    xSemaphoreGiveFromISR(UrrConSem, &woken);
    portYIELD_FROM_ISR(woken);
}

urr_irq_flag и urr_connect_flag можно оставить как счётчики для отладки, но логику строить на семафорах.

10.4 Задача URR вместо polling в main

Создание семафоров в SysAPI_Sem_Init():

UrrFreqSem = xSemaphoreCreateBinary();
UrrConSem  = xSemaphoreCreateBinary();

Объявления в System_API.h:

extern SemaphoreHandle_t UrrFreqSem;
extern SemaphoreHandle_t UrrConSem;

Задача:

static void Urr_Task(void *params)
{
    uint32_t addr = 1;

    urr_init();
    xSemaphoreTake(UrrConSem, pdMS_TO_TICKS(100));

    while (1)
    {
        t_urr_tel tel = urr_get_tel();

        if (tel.connected && tel.ready)
        {
            xSemaphoreTake(UrrFreqSem, 0);   /* сброс старых сигналов */

            urr_get_freqcode(addr);

            if (xSemaphoreTake(UrrFreqSem,
                                pdMS_TO_TICKS(100)) == pdPASS)
            {
                uint32_t freq_code;
                if (urr_read_freqcode(&freq_code) == 0)
                    Sys_Printf("addr=%u freq=0x%06X\n\r", addr, freq_code);
                else
                    Sys_Printf("addr=%u freq ERROR\n\r", addr);

                if (urr_check_crc() == 0)
                    Sys_Printf("CRC OK\n\r");
                else
                    Sys_Printf("CRC FAIL\n\r");
            }
            else
            {
                Sys_Printf("addr=%u irq_o timeout\n\r", addr);
            }
        }
        else
        {
            Sys_Printf("URR not connected or not ready\n\r");
        }

        addr++;
        if (addr > 50) addr = 1;

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

Запуск в Init_Task:

#define URR_TASK_PRIORITY   4
#define URR_TASK_STACK      1024

static TaskHandle_t UrrTaskHandl;
xTaskCreate(Urr_Task, "Urr_Task", URR_TASK_STACK,
            NULL, URR_TASK_PRIORITY, &UrrTaskHandl);

10.5 CRC без busy-wait

Bare-metal версия висит в цикле с usleep(1). В задаче FreeRTOS это плохо — держит CPU.

Было (bare metal)
while (timeout--) {
    uint32_t st = Xil_In32(URR_CRC_STATUS);
    if (st & CRC_STATUS_DONE) { /* ... */ }
    usleep(1);
}
Стало (FreeRTOS)
for (uint32_t i = 0; i < 1000; i++) {
    uint32_t st = Xil_In32(URR_CRC_STATUS);
    if (st & CRC_STATUS_DONE) {
        s_err_crc = (st & CRC_STATUS_MATCH) ? 0 : 1;
        return s_err_crc;
    }
    vTaskDelay(1);   /* ~1 тик, не жжём CPU */
}

Если CRC считается аппаратно за единицы тактов — выгоднее taskYIELD():

while (!(Xil_In32(URR_CRC_STATUS) & CRC_STATUS_DONE)) {
    taskYIELD();
}

10.6 urr_init без XIntc

void urr_init(void)
{
    urr_irq_flag     = 0;
    urr_connect_flag = 0;
    s_connected      = 1;
    s_err_crc        = 0;

    Xil_Out32(URR_CTRL, 0x1);
}

Никаких XIntc_* тут не нужно — всё делает Interrupt_Init().

10.7 Что удалить из bare-metal main.c

  • XIntc_Initialize, XIntc_Connect, XIntc_Start, XIntc_Enable
  • Xil_ExceptionInit, Xil_ExceptionRegisterHandler, Xil_ExceptionEnable
  • init_platform() / cleanup_platform() — их вызывает BSP до main
  • while(1) — он заменяется задачей Urr_Task

Из bare-metal main.c переезжает только логика тела цикла — она становится задачей.

10.8 Порядок вызовов в проекте

  1. main() → xTaskCreate(Init_Task, ...) → vTaskStartScheduler().
  2. Init_Task:
    • Sys_Info_Init, Clear_Err_State, ...
    • SysAPI_Sem_Init() — здесь создать UrrFreqSem, UrrConSem.
    • SysAPI_Irq_Init() — здесь Interrupt_Add_Irq(...) для URR.
    • Interrupt_Init() внутри SysAPI_Irq_Init сам разведёт URR-прерывания в INTC.
    • xTaskCreate(Urr_Task, ...).
  3. Urr_Task работает как отдельная задача.

11. Частые ошибки

Не смешивайте два подхода к INTC

Либо проект использует только Interrupt_Init() и XConnectToInterruptCntrl, либо только XIntc_*. Если в одном проекте вызвать и XIntc_Initialize, и XConfigInterruptCntrl — INTC будет в неопределённом состоянии, и прерывания не пойдут. В вашем проекте выбран первый путь, поэтому URR-драйвер должен следовать ему.

Другие подводные камни
  • Долгое удержание мьютекса или отключение прерываний на большое время — растёт latency.
  • vTaskDelay вместо событийных ожиданий — потеря точности.
  • Priority inversion — лечится через мьютексы с priority inheritance.
  • Переполнение стека задачи — включайте vApplicationStackOverflowHook (у вас он есть в main.c).
  • В TOUT2_Irq_Handle в исходном коде пропущен & перед xHigherPriorityTaskWoken — это ошибка, надо исправить.

Итог

FreeRTOS в двух словах
  • Есть набор задач с приоритетами.
  • Планировщик по тику и событиям выбирает самую приоритетную готовую задачу.
  • Задачи блокируются на семафорах, очередях и задержках.
  • Прерывания будят задачи через ...FromISR.
  • Очереди и семафоры связывают задачи и ISR.
  • Вы не управляете CPU вручную, а описываете, чего задача ждёт.
Что делать с URR
  1. Разнести адреса URR_BASE и MCU_BASE_ADDR.
  2. Убрать из urr.c всё, что касается XIntc.
  3. ISR переписать на xSemaphoreGiveFromISR + portYIELD_FROM_ISR.
  4. Зарегистрировать обработчики через Interrupt_Add_Irq и добавить case-ы в Interrupt.c.
  5. Создать UrrFreqSem и UrrConSem в SysAPI_Sem_Init.
  6. Логику из bare-metal main перенести в Urr_Task.
  7. usleep заменить на vTaskDelay или taskYIELD.
  8. Запустить Urr_Task через xTaskCreate из Init_Task.
