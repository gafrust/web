🗺️ Общая архитектура и порядок работы

Система организована по принципу конвейера: каждый следующий скрипт использует результаты предыдущего.

1_settings → 2_do_hw → 3_do_sw → 4_bit_mcs → result/
ФайлНазначениеТип
1_settings_not_run.sh Центральный конфигурационный файл. Подключается через source, не запускается. bash
_run_me_.sh Главный оркестратор. Последовательно вызывает все скрипты. bash
2_do_hw.sh + .tcl Аппаратная сборка. Синтез, имплементация, битстрим. bash + tcl
3_do_sw.sh + .tcl Программная сборка. Платформа, BSP, приложение, .elf. bash + tcl
4_bit_mcs.sh Финальная сборка. Объединение .bit + .elf, генерация .mcs. bash + tcl
write_bit_to_fpga.sh Прошивка FPGA через JTAG. bash + tcl
write_mcs_to_flash.sh Прошивка флеш (устаревший метод через impact). bash
write_mcs_to_flash_viv.sh Прошивка флеш (новый метод через Vivado HW Manager). bash + tcl

⚙️ 1. 1_settings_not_run.sh — Конфигурация

Единая точка настройки. Только экспортирует переменные окружения.

ПеременнаяНазначениеЗначения
NEW_BOARDРевизия платы1 — новая (2-канальная), 0 — старая
SRC_BDПуть к .bdВычисляется из NEW_BOARD
SRC_SWИсходники C для Vitis../VITIS_sources
BUILDКаталог результатов../build
PRJ_NAMEИмя проекта VivadoUKL_M_v1
GEN_IPФлаг генерации IP1 — генерировать, 0 — готовые
Важно: при первой сборке установите GEN_IP=1, при последующих — GEN_IP=0, чтобы не тратить время на регенерацию IP-ядер.

🎯 _run_me_.sh — Оркестратор

Главный скрипт, который запускает всю цепочку с проверкой статусов на каждом этапе.

# Псевдокод логики:
source 1_settings.sh
if GEN_IP == 1: SYN_with_IP.sh  # генерация IP
if GEN_IP == 0: SYN_without_IP.sh

source 2_do_hw.sh   → RESULT_HW
  if RESULT_HW == 0:
    source 3_do_sw.sh  → RESULT_SW
    if RESULT_SW == 0:
      source 4_bit_mcs.sh → RESULT_BITMCS
      if RESULT_BITMCS == 0: "Done"

Каждый скрипт возвращает переменную-результат (RESULT_HW, RESULT_SW, RESULT_BITMCS), которая равна 0 при успехе и -1 при ошибке.

🏗️ 2. Аппаратная сборка: 2_do_hw.sh + 2_do_hw.tcl

📜 2_do_hw.sh — подготовка

  1. Подключает настройки: source ./1_settings_not_run.sh
  2. Создаёт резервную копию: cp -r ${BUILD} ${BUILD}_old
  3. Очищает и создаёт директорию сборки
  4. Копирует .bd, *.ipdefs, *.xdc в новую структуру
  5. Запускает Vivado в batch-режиме
  6. Возвращает RESULT_HW

💻 3. Программная сборка

📜 3_do_sw.sh — координация

Находит проект *.xpr, экспортирует .xsa через Vivado, затем запускает XSCT.

🔧 4. Финальная сборка: 4_bit_mcs.sh

Объединяет аппаратную и программную части в один файл прошивки.

Шаг 1: Объединение .bit и .elf

updatemem -force -meminfo ${NAME_BD}.mmi \
    -data ../../${PRJ_NAME}.sdk/ukl7m/Release/ukl7m.elf \
    -proc Top_level_i/microblaze_0 \
    -bit ${NAME_BD}.bit \
    -out ../../result/ukl7m_micro_init_mem.bit

ELF-файл встраивается в битстрим, чтобы MicroBlaze сразу загрузил программу из памяти.

Шаг 2: Генерация .mcs

write_cfgmem -format mcs -force -interface spix4 -size 32 \
    -loadbit "up 0x0 ukl7m_micro_init_mem.bit" \
    -file ukl7m_micro_init_mem.mcs

write_cfgmem — ключевая команда для создания конфигурационного файла памяти.

Документация: UG908 (Programming and Debugging), UG835.

💾 Прошивка флеш-памяти

📜 Старый метод: write_mcs_to_flash.sh

Использует утилиту iMPACT (устаревшую, но поддерживаемую для 7-й серии ПЛИС).

Команда iMPACTНазначение
setMode -bsРежим Boundary Scan
setCable -port autoАвтоопределение кабеля
Identify -inferirИдентификация цепочки JTAG
attachflash -position 1 -spi "W25Q64FV"Подключение SPI-флеш
assignfiletoattachedflashНазначение MCS-файла
Program -p 1 -dataWidth 4 -spionly -e -v -loadfpgaСтирание + программирование + верификация

📜 Новый метод: write_mcs_to_flash_viv.sh

Использует Vivado Hardware Manager и объект hw_cfgmem.

PROGRAM.ERASE 1Включает стирание
