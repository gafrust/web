📁 Генерация нетлиста Vivado для модуля uart_top

Цель: создать функциональный Verilog нетлист (для симуляции в ModelSim) из RTL-исходников проекта UART с сохранением атрибутов IOB и DONT_TOUCH.

2. Содержимое скрипта viv_uart_top.tcl

Скрипт выполняет полный цикл: создание проекта, добавление файлов, синтез, оптимизация, размещение, трассировка и генерация нетлиста.

# ============================================================
# Скрипт синтеза и генерации нетлиста для модуля uart_top
# Платформа: xc7a35tftg256-1, Vivado 2023.2
# ============================================================

set partname xc7a35tftg256-1
set module uart_top

# Создаём проект в текущей папке (силовая перезапись)
create_project -force $module . -part $partname

# Добавляем все RTL-файлы из папки ../rtl
add_files [glob ../rtl/*.v ../rtl/*.sv]

# Запускаем синтез
synth_design -top $module -part $partname

# Сохраняем checkpoint после синтеза (опционально)
write_checkpoint -force -noxdef $module.dcp

# ------ Полный маршрут (оптимизация, размещение, трассировка) ------
opt_design
place_design
phys_opt_design
route_design

# Сохраняем routed checkpoint
write_checkpoint -force $module-routed.dcp

# ------ Генерация нетлиста для симуляции (функциональный) ------
write_verilog -force ./verilog/$module.v

# Закрыть проект (чтобы не засорять память)
close_project

puts "=== Генерация нетлиста завершена. Файл: ./verilog/$module.v ==="

Пояснения по командам:

КомандаНазначение
create_project -forceСоздаёт проект, перезаписывая существующий (удобно при повторных запусках).
add_files [glob ...]Добавляет все Verilog и SystemVerilog файлы из папки ../rtl.
synth_designЗапускает синтез с указанным топ-модулем и микросхемой.

3. Запуск скрипта

  1. Откройте терминал и перейдите в папку sim_syn: 
    cd /home/rgafurov/work/Praktika_FPGA/Rustem_Gafurov/Radiocomp/URR3/3_fifo/URR/sim_syn
  2. Запустите Vivado в пакетном режиме с указанием скрипта: 
    vivado -source viv_uart_top.tcl -mode batch
  3. Если требуется сохранить логи, можно перенаправить вывод: 
    vivado -source viv_uart_top.tcl -mode batch | tee vivado.log

4. Что делать при ошибках

Ошибка 1: «Project already exists»
Добавьте флаг -force в команду create_project (как в скрипте выше). Либо удалите старый проект вручную: rm -rf uart_top.xpr uart_top.cache uart_top.hw uart_top.ip_user_files.
Ошибка 2: «no clock signal specified in event control»
Возникает, если в always-блоке используется posedge rst и внутри if (!rst). Решение – перейти на синхронный сброс (только posedge clk, внутри if (rst)). Пример исправления для FIFO и bram_interface_urr дан в описании.
Ошибка 3: «width mismatch» для порта count в FIFO
В urr_crc.v порт count имеет ширину 8 бит, а модуль fifo возвращает 9 бит. Для устранения объявите wire [8:0] fifo_count; и подключите его. Но это не критично для синтеза – Vivado выдаёт предупреждение, но не ошибку.
Успешное завершение – в логе должны отсутствовать ошибки, а в конце появится сообщение «Генерация нетлиста завершена».

6. Как адаптировать скрипт для другого модуля

  1. Измените переменные в начале скрипта: 
    set partname <ваша_микросхема>
set module <имя_топ_модуля>
  2. Убедитесь, что все исходные файлы лежат в папке, указанной в add_files. При необходимости измените путь.
  3. Если есть IP-ядра, их нужно добавить отдельно командой add_files с путём к DCP-файлу или через import_ip.
  4. Если XDC-файл обязателен, раскомментируйте строку add_files ../xdc.xdc и укажите правильный путь.

7. Дополнительные возможности

  • Генерация только после синтеза (быстрее, но без учёта размещения): закомментируйте строки с opt_design … route_design и переместите write_verilog сразу после synth_design.
  • Отчёты по ресурсам и таймингу – добавьте в конец скрипта: 
    report_utilization -file $module-util.txt
report_timing_summary -file $module-timing.txt
  • Сохранение нетлиста с таймингами – замените write_verilog на write_verilog -mode timesim -force ./verilog/$module_timesim.v.

10. Часто задаваемые вопросы

Нужно ли запускать synthesis через GUI, чтобы получить нетлист?
Нет, скрипт делает всё автоматически. Результат – готовый файл .v.
Можно ли использовать этот нетлист в ModelSim?
Да, это стандартный функциональный нетлист, совместимый с симуляторами.
Атрибуты IOB и DONT_TOUCH сохраняются?
Да, Vivado переносит все (* ... *) атрибуты из RTL в нетлист.
Что делать, если синтез падает с ошибкой «Project already exists»?
Используйте -force в create_project или удалите старый проект вручную.
